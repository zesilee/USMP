实到 69 个文件有改动）沉淀下来的方法与坑。适用于任何「声称不改变行为」的重构：
注释清理、格式化、纯重命名、注解调整。

## 一、别用人眼看 diff 证明「代码没动」——用机器指纹

**后端 Go**：`go/scanner` 逐文件扫 token 流（`s.Init(..., 0)`，mode 0 不返回 COMMENT
token），把每个 token 的 `tok.String()` + `lit` 拼进 sha256。标识符、字面量、运算符、
struct tag 任意一处变化都会暴露；注释与空白的增删改完全透明。

**前端 TS/TSX**：`esbuild.transform`（`minifyWhitespace: true`、`minifyIdentifiers: false`、
`minifySyntax: false`、`legalComments: 'none'`、`jsx: 'preserve'`）后哈希。
esbuild 在 `frontend/node_modules/esbuild/lib/main.js`，无需额外装包。

**取基线的正确姿势**：`git archive HEAD <path> | tar -x -C <临时目录>`。
不要用 `git stash`——stash 栈与主仓和其他 worktree 共享，会和别的会话抢（见
[[branch-sync-and-bulk-delete-gotchas]]）。

## 二、坑：go/printer 做指纹会误报

第一版用 `parser.ParseFile(..., 0)`（不解析注释）+ `go/printer` 打印后哈希，结果
`internal/api/server.go` 报「代码变了」，实际 diff 里全是注释删除。

**根因**：`go/printer` 依据源码**行号**决定空行输出。删掉一行注释会让后续代码行号
整体前移，打印结果随之变化。AST 不含注释 ≠ 打印结果不受注释影响。

**结论**：位置无关的 token 流才是对的载体，别用打印器。

## 三、本仓「长得像注释、实为功能指令」清单（删一条就出事）

改注释前先建立这份清单并**逐类清点改动前后的数量**，任一类少一条即为事故。
2026-08-25 实测基线：

| 形态 | backend | frontend/src | 说明 |
|---|---|---|---|
| `// @`（swag 注解） | **187** | 2 | `internal/api/` 全是；删一行掉 OpenAPI，前端契约漂移门禁直接红 |
| `// +kubebuilder:*` | **18** | 0 | `backend/api/core/v1/`，CRD 生成靠它 |
| `//go:*` | 8 | 0 | 含 `//go:embed schema.ir.gz`（构建期产物嵌入）、`//go:generate`、`//go:build tools` |
| `//nolint` | 1 | 0 | |
| `eslint-disable` | 0 | **19** | 组件里密集，尤其 `react-hooks/exhaustive-deps` |
| `/// <reference` | 0 | 1 | `src/vite-env.d.ts` 几乎只有这一行 |
| `DO NOT EDIT` | 28 | 0 | 生成物标记 |

**最隐蔽的一类**：`backend/tools/` 下生成器**模板字符串内**的注释文本（反引号或引号
包裹的 `// Code generated by ...`）。它是字符串字面量，改了会让 `internal/generated/*`
全量重生成、触发 regen-and-diff 门禁。判据：在字符串里就一律不动。

## 四、两套行数门禁口径不同，别只看 TM04

- `.githooks/commit-msg`：**单次 commit ≤500 行**（纯删除 ≤6000）
- `.github/workflows/pr-size.yml`：PR ≤1000 行；**>20 文件按 infra PR 放宽到 3000**；
  insertions ≤50 的纯删除 PR 放宽到 6000

本次 531 行的单 commit 被 commit-msg 拦下（PR 层面 3000 完全够用），按后端 448 /
前端 83 拆两个 commit 才过。**规划提交粒度时以 500 为准，不是 1000。**

## 六、多代理切分的实践口径

- 按**目录**切、保证互不重叠（TM03），一个代理一块，8 块并行没有冲突。
- 规范写成**一份共享 md 文件**让每个代理先读，别把规则复制进 8 份 prompt——
  复制会漂移。prompt 里只放该批次特有的风险提示（如「你这块 swag 注解最多」）。
- 要求代理如实产出「需人工复核项」，别让它自己拍板删。本次 8 个代理共报出 20 余条，
  其中挖出 5 处存量代码问题（吞错误、裸 `fmt.Printf` 等），已归档 B 段。
- 语言策略必须显式钉死：本仓后端英文 doc comment 为主、前端中文为主，
  **不做中英互译**，否则代理会顺手「统一」成一种语言，那是重写不是清理。
