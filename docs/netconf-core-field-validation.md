# 自研 NETCONF 引擎真机验证手册 —— 交测试团队

> 背景：USMP 的 NETCONF 通道已完成自研替代（netconfcore，2026-08-04 Wave 1-4
> 软件部分全部合入）。因**交付红线 NC-01（版本交付编译不得依赖 scrapligo）**，
> 旧引擎已从代码与依赖中移除——**自研引擎是当前唯一引擎**，无运行时回退开关。
> 软件面等价性已验证（原 scrapligo 全量行为测试套在新引擎上全绿 + 模拟网元
> 端到端）；真机边角行为是唯一未验证敞口，实验室 IP 不可达，由测试团队补测。
> 结论回传前请勿将含本引擎的版本用于生产设备变更。
> 总纲/决策记录：`openspec/tasks/netconf-client-selfdev.md`。

## 1. 验证对象与准备

- 任一 2026-08-04 之后构建的 USMP 版本（发布 zip 或镜像）即含自研引擎，无需
  任何开关。确认方法：`go version -m usmp-backend | grep scrapli` 应无输出。
- 需要：一台可达的华为 CE 交换机（测试网段）、NETCONF 使能（SSH 830）、账号。
- **回退方案**：本引擎无并行旧引擎可切；如遇阻断性问题，回退到 2026-08-04
  之前的旧版本发布包（含 scrapligo），并把日志反馈开发在 netconfcore 修复。

## 2. 验证清单（按优先级）

每项均为「旧引擎已验证过的现网行为」，验证目标 = 新引擎在真机上同样表现。

| # | 项目 | 操作 | 预期 |
|---|------|------|------|
| V1 | 连接与握手 | 设备管理页注册真机（IP/账号），观察设备状态 | 在线；后端日志无 hello/协商报错。**真机会走 1.1 chunked 封帧**（模拟器只走 1.0），这是头号验证目标 |
| V2 | 全量配置回读 | 打开任一模块控制台（如 VLAN/接口），点「获取数据」 | 表格正常出数；配置量大的模块（BGP/QoS）完整不截断——验证大回包多分块重组 |
| V3 | 配置下发与收敛 | 新建/修改/删除一个 VLAN，等待对账收敛 | 下发成功、回读一致、无漂移告警 |
| V4 | 两阶段提交 | 业务网络配置（多设备 VLAN 打通）走一次下发 | confirmed-commit 链路正常：成功即生效，中断自动回滚 |
| V5 | 断线自愈 | 下发成功后拔线/重启设备，恢复后再操作 | 首次操作可能报错，随后自动重连恢复；**不得**出现「持续 500 EOF 直到重启后端」 |
| V6 | 并发压力 | 模块控制台并行展开多个子树（前端本就并行拉取） | 全部正常返回，无超时、无错乱数据 |
| V7 | 运维 RPC | 左树选一个 rpc（如清计数）执行 | 成功/失败反馈明确，高危操作有确认 |
| V8 | 稳定性 | 常规操作持续 ≥24h | 无内存异常增长、无连接泄漏（`ss` 观察设备方向连接数稳定） |

## 3. 需要留证的东西

- 后端日志（含时间戳）；失败项加设备侧 NETCONF 会话日志（若可取）。
- 每项结论记入 `openspec/tasks/netconf-client-selfdev.md` Wave 4 段（或反馈开发代记）。

## 4. 已知差异（预期内，不算缺陷）

- 报错文案与旧版不同（更结构化），但成功/失败判定口径一致。
- 操作无显式超时时缺省 60 秒截止（与旧引擎同量级）。
