# 自研 NETCONF 引擎（core）真机验证手册 —— 交测试团队

> 背景：USMP 已完成 scrapligo 第三方库的自研替代（Wave 1-3，2026-08-04），新旧
> 引擎双路径并行，**现网缺省仍为旧引擎（scrapligo），行为零变化**。软件面等价性
> 已由 CI 锁定（整套 client 测试在两引擎上各自全量通过）；剩余唯一验证敞口是
> 华为 CE 真机的协议边角行为。本手册供测试团队独立执行真机灰度。
> 总纲/决策记录：`openspec/tasks/netconf-client-selfdev.md`。

## 1. 如何切到自研引擎

给后端进程加环境变量（**只影响该进程，不改代码不改镜像**）：

| 部署形态 | 做法 |
|----------|------|
| docker compose | `docker-compose.yml` 的 backend 服务 `environment` 增加 `USMP_NETCONF_IMPL: "core"` 后 `docker compose up -d backend` |
| K8s | Deployment 的容器 env 增加 `USMP_NETCONF_IMPL=core` 滚动重启 |
| 本地二进制 | `USMP_NETCONF_IMPL=core ./usmp-backend` |

**回退**：删掉该环境变量重启即回旧引擎（秒级，无数据迁移）。任何一项验证失败
都先回退恢复业务，再把日志交回开发。

## 2. 验证清单（按优先级）

每项均为「旧引擎已验证通过的现网行为」，验证目标 = 新引擎在真机上同样表现。

| # | 项目 | 操作 | 预期 |
|---|------|------|------|
| V1 | 连接与握手 | 设备管理页注册真机（IP/账号），观察设备状态 | 在线；后端日志无 hello/协商报错。**真机会走 1.1 chunked 封帧**（与模拟器不同），这是本次验证的头号目标 |
| V2 | 全量配置回读 | 打开任一模块控制台（如 VLAN/接口），点「获取数据」 | 表格正常出数；配置量大的模块（BGP/QoS）也完整不截断——验证大回包多分块重组 |
| V3 | 配置下发与收敛 | 新建/修改/删除一个 VLAN，等待对账收敛 | 下发成功、回读一致、无漂移告警 |
| V4 | 两阶段提交 | 业务网络配置（多设备 VLAN 打通）走一次下发 | confirmed-commit 链路正常：成功即生效，中断自动回滚 |
| V5 | 断线自愈 | 下发成功后拔线/重启设备，恢复后再操作 | 首次操作可能报错，随后自动重连恢复；**不得**出现「持续 500 EOF 直到重启后端」 |
| V6 | 并发压力 | 模块控制台并行展开多个子树（前端本就并行拉取） | 全部正常返回，无超时、无错乱数据 |
| V7 | 运维 RPC | 左树选一个 rpc（如清计数）执行 | 与旧引擎同样的成功/失败反馈 |
| V8 | 稳定性 | core 引擎跑 ≥24h 常规操作 | 无内存增长异常、无连接泄漏（`ss` 观察设备方向连接数稳定） |

## 3. 需要留证的东西

- 后端日志（含时间戳）；失败项加设备侧 NETCONF 会话日志（若可取）。
- 每项结论记入 `openspec/tasks/netconf-client-selfdev.md` Wave 4 段（或反馈开发代记）。

## 4. 通过后的收官（开发执行，测试不用做）

全部通过 → 开发将缺省切至 core、删除 scrapligo 依赖与其补丁代码（约定见任务
文件 Wave 4 门禁：**测试结论回来前不切缺省、不删旧引擎**）。

## 5. 已知差异（预期内，不算缺陷）

- 新引擎对报错的文案略有不同（更结构化），但「成功/失败」判定与旧引擎一致。
- 操作无显式超时时新引擎缺省 60 秒截止（旧引擎同量级）。
